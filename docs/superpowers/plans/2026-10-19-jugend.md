# Jugend (JD/JM) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** AVplan plans Sunday youth classes and Wednesday youth activities (JD/JM), with a login-free youth overview page, an idea pool, break periods and a one-off Airtable import.

**Architecture:** New tables (`youth`, `youth_leaders`, `youth_events`, `youth_event_parts`, `youth_event_adults`, `youth_ideas`, `youth_breaks`) next to the existing `meetings`; server modules under `src/lib/server/youth*.ts`; routes `/jugend/**` (app) and `/j/[token]` (public). The event page copies the Sunday page pattern: forms per section, autosave on change, per-section version fingerprints, live channel via the existing POST hook.

**Tech Stack:** SvelteKit 2 / Svelte 5 runes, Drizzle + better-sqlite3, vitest, ExcelJS (CSV reading for the import).

**Spec:** `docs/superpowers/specs/2026-10-19-jugend-design.md`

## Global Constraints

- Code, identifiers, comments and test titles in English; UI strings, URLs and persisted enum values German (`CLAUDE.md`).
- Comments only where code cannot explain itself.
- Every editing page: autosave on change, per-section `version` hidden field checked server-side (409 → `fail(409, { error })`), no save button. The hook already publishes a live `change` event on every successful POST.
- Tests use fictional names only (Dürst, Rey, Koller, Gasser, Baumann, Widmer; Urs, Reto, Vreni, Lea, Mia). Run `npm test` and `npm run check` before each commit.
- Commits authored by Philipp Spinnler only, no co-author lines, no personal data.
- Migration after every schema change: `npm run db:generate` (creates `drizzle/000N_*.sql`; commit it).

## Review Focus

1. A Wednesday inside a `ferien` break where a leader already typed an activity must show as taking place, not as cancelled (Task 4 test `break does not cancel a Wednesday that has content`).
2. A Sunday whose `meetings` row is `generalkonferenz`/`pfahlkonferenz`/`ostern`/`weihnachten`/`keine` must show as cancelled on list and youth page even when a `youth_events` row with content exists (Task 4 test `classHeld follows the meeting kind`).
3. Switching `joint` on and off must not lose text: on → one `both` part containing JD text then JM text; off → both sides get the joint text (Task 4 test `toggling joint merges and splits parts`).
4. The youth page with a wrong or missing token must 404 and never leak data; with the right token it must show first names only (Task 8 tests).
5. A JM-Berater posting to the JD section must get 403, also for a `both` part when they lack both rights — the matrix test in Task 1 plus the action test in Task 7.

  - `SUNDAY_KINDS = ['klasse','erwachsene','keine']`, `WEDNESDAY_KINDS = ['aktivitaet','basel','fireside','uebertragung','pfahl','tempel','ferien','keine']`, `OFF_KINDS = ['erwachsene','pfahl','tempel','ferien','keine']`
  - `classHeld(kind: MeetingKind): boolean` = `hasProgram(kind) && kind !== 'ostern' && kind !== 'weihnachten'`
  - `ensureYouthEvents(db, fromIso, months = 6): number` (creates missing rows: Sundays `klasse`, Wednesdays `aktivitaet`)
  - `interface YouthPartFull { side: YouthPartSide; text: string | null; leader: Member | null; leaderGroup: string | null; thought: Member | null }`
  - `interface YouthEventFull { event: YouthEvent; weekday: 'sunday' | 'wednesday'; parts: YouthPartFull[]; adults: { member: Member; present: boolean }[]; meetingKind: MeetingKind | null; break: YouthBreak | null; status: 'off' | 'open' | 'planned'; offLabel: string | null }`
  - `loadYouthEvent(db, date): YouthEventFull | null` — resolves `status`: Sunday with meeting row and `!classHeld(kind)` → off with `KIND_LABELS[kind]`; `kind in OFF_KINDS` → off with `YOUTH_KIND_LABELS[kind]` (+ `details` if set); Wednesday inside a break and `isOpen` → off with break label; else `planned` when any part has `text || leader || leaderGroup || thought`, otherwise `open`. `isOpen` = kind is the weekday default and no part has content.
  - `listYouthEvents(db, from, to): YouthEventFull[]` — one entry per date from `youthDatesBetween`, rows loaded in one query, missing rows synthesized as open defaults (not persisted).
  - `saveYouthCommon(db, eventId, input: { kind; joint; details; topic; topicUrl; snack }): void` — when `joint` changes: on → merge parts into one `both` (`text` = JD text + '\n' + JM text if both, leader/thought from JD); off → `jd` and `jm` both get the `both` text/leader/thought.
  - `saveYouthPart(db, eventId, side: YouthPartSide, input: { text; leaderMemberId; leaderGroup; thoughtMemberId }): void` (upsert; `side==='both'` only if `joint`, else throws)
  - `saveYouthAdults(db, eventId, entries: { memberId; present: boolean | null }[]): void` (null deletes the row)
  - `youthSectionVersions(full): Record<'common'|'jd'|'jm'|'both'|'adults', string>` (sha1 slices like `sectionVersions`)
  - `isFifthSunday(iso): boolean`
